# dns-whitelist — design spec

**Date:** 2026-10-07
**Status:** Approved (pending user review)
**Author:** OpenCode orchestration session

## Purpose

Build and maintain a curated, auto-refreshing allowlist of DNS names consumed
by AdGuard Home, so users behind AdGuard's default blocklists can still use
six specific services without whack-a-mole:

1. Microsoft Authenticator
2. Google Authenticator
3. NetIQ (Access Manager / Identity Manager)
4. Cisco AnyConnect (Cisco Secure Client)
5. Palo Alto GlobalProtect
6. Microsoft Teams

The repo hosts the script that generates the allowlist, the per-service
catalog, the generated `whitelist.txt`, and the GitHub Actions that keep it
fresh.

## Design decisions (locked)

| # | Decision | Rationale |
|---|---|---|
| 1 | **AdGuard allowlist syntax** (`@@||domain.com^`) with `# ===` sections per service | Native to AdGuard Home; still importable as a filter list. Targeted rules prevent breakage without over-permitting. |
| 2 | **Auto-fetch vendor URLs** via a Python build script | Vendor-published URLs are stable and machine-readable; automation is the only way to keep the list honest as services change. |
| 3 | **Weekly schedule + manual dispatch** trigger | Weekly catches slow vendor changes; manual dispatch covers an immediate refresh after a known incident. |
| 4 | **Targeted scope** — only domains that blocklists actually break | Smaller surface; lower false-positive risk; less chance of bypassing intentional blocks (ads, trackers). |
| 5 | **Lint + DNS-resolve verification** | Lint catches typos; DNS resolve drops dead domains (which can't be in any blocklist collision). |
| 6 | **Global rules** (no `$client` modifier) | Simplest; fits the typical home-network case. |
| 7 | **Python 3 + requests + dnspython + pyyaml** | Standard tooling on GH Actions runners; mature JSON/HTML parsing; clean DNS API; readable source. |

## Architecture

```
   +-----------------------+
   | sources/*.yaml        |  (one YAML per service — vendor URL, parser, filter)
   +-----------+-----------+
               |
               v
   +-----------------------+
   | scripts/build.py      |  entry point, deterministic, idempotent
   +-----------+-----------+
               |
   +-----------+-----------+-----------+
   | fetch.py | lint.py | resolve.py  |
   +-----------+-----------+-----------+
               |
               v
   +-----------------------+
   | whitelist.txt         |  (generated, never hand-edited)
   +-----------------------+
```

Components are small, single-purpose, and independently testable:

- **`fetch.py`** — HTTP fetch with retry (3 attempts, exponential backoff) and `.cache/` (24h TTL).
- **`lint.py`** — strict RFC-1035-ish domain syntax check.
- **`resolve.py`** — parallel DNS resolve via `1.1.1.1` and `8.8.8.8` using `dnspython`.
- **`parsers/`** — one module per source family: `json_endpoint`, `html_grep`, `csv_table`. New formats are additive; existing services don't regress.
- **`build.py`** — orchestrator: reads `sources/*.yaml`, dispatches to the right parser, runs each candidate through lint → resolve, dedupes, sorts, and writes `whitelist.txt`.

## Generated `whitelist.txt` shape

```
# dns-whitelist — AdGuard Home allowlist
# Generated by scripts/build.py. Do not edit by hand.
# Last refreshed: 2026-10-07 (UTC)
# See README.md for usage.

# === Microsoft Teams ===
# Source: https://learn.microsoft.com/.../urls-and-ip-address-ranges
@@||teams.microsoft.com^
@@||teams.live.com^

# === Microsoft Authenticator ===
# Source: ...
@@||login.microsoftonline.com^

# === Google Authenticator ===
...

# === NetIQ ===
...

# === Cisco AnyConnect ===
...

# === Palo Alto GlobalProtect ===
...
```

- AdGuard allowlist syntax (`@@||domain^`).
- Sections per service with `# ===` headers.
- Each section header includes the source URL.
- Global scope (no `$client` modifier).
- File is **generated** — humans edit `sources/*.yaml`, never the .txt.

## Per-service `sources/<service>.yaml` shape

```yaml
service: Microsoft Teams
source_url: https://learn.microsoft.com/en-us/microsoft-365/enterprise/urls-and-ip-address-ranges
fetch:
  type: json_endpoint_list
  url: https://endpoints.office.com/endpoints/worldwide
  domain_keys: [urls]
  filter: require=optimize
output_section: Microsoft Teams
```

Adding a service = adding one YAML + (only if needed) one small parser.

## Update flow

1. **Trigger**: weekly schedule (`cron: '0 6 * * 1'` — Mondays 06:00 UTC) **OR** manual `workflow_dispatch` input.
2. **Runner**: `ubuntu-latest`, Python 3.11 (preinstalled).
3. **Steps**:
   1. Checkout repo
   2. `pip install -r requirements.txt`
   3. `python scripts/build.py --out whitelist.txt`
   4. `git diff --quiet whitelist.txt` — exit 1 if diff is non-empty
   5. On diff: open PR titled `chore: refresh whitelist (YYYY-MM-DD)`, body lists added/removed entries (sorted, deduplicated)
4. **Permissions**: `contents: write`, `pull-requests: write`.
5. **Manual run**: `gh workflow run refresh-whitelist.yml` for an ad-hoc refresh.

## Verification

Each candidate domain must pass two gates before being written to `whitelist.txt`:

| Gate | What it does | Failure mode |
|---|---|---|
| **Domain syntax lint** | RFC-1035-ish regex: labels 1–63 chars, total ≤ 253, LDH-only, no leading/trailing hyphens | Hard fail with offending line + abort build |
| **DNS resolve** | Resolve via `dnspython` against `1.1.1.1` and `8.8.8.8` in parallel; both must answer | Soft fail — drop the candidate and continue, log a warning |

Rationale for soft-failing DNS: in a targeted allowlist, an unresolvable domain can't be in any blocklist collision, so it doesn't belong. But we don't want one flaky vendor to break the whole build.

## Error handling

- **HTTP**: `requests` with 3 attempts, exponential backoff, 30s timeout per attempt. Persistent failure aborts with the failing URL surfaced.
- **Parser errors**: `try/except` per source; one bad source doesn't kill the others.
- **Idempotency**: `scripts/build.py` is pure (reads `sources/`, writes `whitelist.txt`); safe to run repeatedly. Output is deterministic modulo source order.
- **Cache**: vendor responses cached in `.cache/` (gitignored) with 24h TTL.
- **Secrets**: none. All vendor URLs are public.

## Testing

- `pytest scripts/test/` with fixtures under `scripts/test/fixtures/`.
- **Unit**: each parser extracts correctly from its fixture; lint catches malformed domains; DNS resolve is mocked via `monkeypatch` on `dnspython`.
- **Golden**: full `build.py` run against fixtures is byte-identical to a checked-in `scripts/test/fixtures/golden-whitelist.txt`.
- **Lint**: `ruff check scripts/` (config in `pyproject.toml`).
- **CI**:
  - `test.yml` — runs `ruff` + `pytest` on every PR.
  - `refresh-whitelist.yml` — runs on schedule + dispatch + manual; only opens a PR if the diff is non-empty.

## Initial service coverage

| Service | Source | Format | Confidence |
|---|---|---|---|
| Microsoft Teams | `https://endpoints.office.com/endpoints/worldwide` | JSON | High |
| Microsoft Authenticator | Same Microsoft 365 endpoints catalog | JSON | High |
| Google Authenticator | `https://support.google.com/a/answer/10026322` + small curated set | Mixed (HTML + manual) | Medium |
| NetIQ | `https://www.netiq.com/documentation/` | HTML, scattered | Low |
| Cisco AnyConnect | Cisco hosts-file allowlist docs | XML / HTML | Medium |
| Palo Alto GlobalProtect | `https://docs.paloaltonetworks.com/globalprotect` | HTML | Medium |

The first three are likely to work end-to-end on Phase 1. The last three are
research-heavy and may need a manual-discovery step where the maintainer
either hand-codes the YAML with the FQDNs or identifies an undocumented
JSON/XML endpoint that we can fetch.

## Phase 1 scope

Deliver the framework + one full vertical example, then leave the remaining 5 services as additive YAML-only changes.

1. Repo scaffolding (`README.md`, `requirements.txt`, `pyproject.toml` for ruff).
2. `scripts/build.py` + library modules (`fetch.py`, `lint.py`, `resolve.py`).
3. One parser module (`parsers/json_endpoint.py`) — covers Microsoft365 catalog (Teams + Authenticator).
4. Two sources YAMLs: `microsoft-teams.yaml`, `microsoft-authenticator.yaml`.
5. First `whitelist.txt` committed (generated, reviewed by the repo in commit).
6. `scripts/test/` with at least one fixture-driven golden test.
7. `.github/workflows/test.yml` + `.github/workflows/refresh-whitelist.yml`.
8. AGENTS.md updated to reflect real tooling (replace TODO placeholders).
9. README quickstart (how to consume + how to contribute a new service).

## Phase 2 (post-Phase-1)

Add the remaining 4 services one at a time:

- Google Authenticator (likely needs `parsers/html_grep.py`)
- Cisco AnyConnect (parser may need XML)
- Palo Alto GlobalProtect (`html_grep.py` again)
- NetIQ (likely hand-curated YAML referencing docs)

Each addition is bounded: one YAML, optionally one parser, one new test fixture, one PR.

## YAGNI — what we're NOT building

- ❌ Version pinning of vendor URLs — over-engineering; the refresh workflow catches breakage.
- ❌ Multi-consumer output formats (Pi-hole, NextDNS, dnsmasq). AdGuard is the named target; others can fork.
- ❌ A web UI / dashboard.
- ❌ IP-based entries (`@@||1.2.3.4$network`). Domain-only per the format choice.
- ❌ Notification integrations (no Slack/email). The PR is the notification.
- ❌ Acceptance of user-submitted domains via PRs to `whitelist.txt` directly. Only via `sources/*.yaml` + a passing build.

## Open questions for Phase 2

- None blocking Phase 1. Phase 2 services will surface their own questions as we hit each vendor's documentation.
